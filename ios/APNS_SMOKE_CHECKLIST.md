# APNs smoke checklist

Проверка выполняется на физическом iPhone: симулятор не получает реальные APNs.

- Git commit:

- Итог: PASS / FAIL

## Подготовка

- [ ] Установить свежую Debug- или TestFlight-сборку.
- [ ] Убедиться, что bundle ID совпадает с APNs topic.
- [ ] В Settings указать server URL и API key, нажать **Save Settings**.
- [ ] Разрешить уведомления в системных настройках.
- [ ] Нажать **Request Push Registration** и убедиться, что появился device token.
- [ ] Проверить `Check Server Health`.

## Основной сценарий

- [ ] Для режима `all` создать задачу на Mac и получить push.
- [ ] Для режима `tax` получить push от приложения `tax` и не получить его от другого app source.
- [ ] Для режима `off` убедиться, что задача появилась в списке, но push не пришёл.
- [ ] Вернуть требуемый режим и создать задачу командой `tax run ...`.
- [ ] Получить уведомление, когда приложение в background.
- [ ] Нажать уведомление и убедиться, что открылась правильная задача.
- [ ] Получить уведомление в foreground; проверить banner и обновление списка.
- [ ] Отправить reply из приложения.
- [ ] Отправить reply через notification action **REPLY** для новой задачи.
- [ ] На Mac убедиться, что оба ответа получены.
- [ ] На backend убедиться, что обработанный ответ получил статус `delivered`.

## Восстановление после сети

- [ ] Отключить сеть на iPhone.
- [ ] Попытаться обновить задачу или отправить reply; проверить понятную ошибку и сохранение текста.
- [ ] Включить сеть и повторить действие через Retry/Send.
- [ ] Убедиться, что ответ доставлен один раз.

## Критерий PASS

Все обязательные пункты выполнены; расхождения зафиксированы ссылками на дефекты. APNs environment соответствует типу сборки: sandbox для Debug и production для TestFlight/App Store.
