# Тёмный редизайн iOS-приложения без изменений терминала

## Goal

Применить заданную тёмную дизайн-систему ко всем экранам, кроме терминала: списку workspace, деталям workspace, файловому браузеру, редактору, превью и настройкам. Сохранить бизнес-логику, существующие статусы, действия и навигацию.

## Context

- Приложение использует SwiftUI, Swift 6, strict concurrency, iOS 17+. Предупреждения Swift считаются ошибками.
- `tax/tax/Views/WorkspaceListView.swift` отображает workspace и управляет переходами, включая push deep links.
- `tax/tax/Views/WorkspaceView.swift` отображает терминальные сессии и переход к файлам; содержит создание, переименование и закрытие сессий.
- `tax/tax/Views/FileBrowserView.swift` содержит браузер, поиск, редактор текста, Markdown- и image-превью.
- `tax/tax/Views/SettingsView.swift` использует `Form` для настроек подключения, ключей и уведомлений.
- `ContentView.swift` и `Info.plist` задают светлое оформление приложения. Терминал имеет собственное оформление.
- `ConnectionStatus` объявлен в `WorkspaceListView.swift`, но также используется терминалом. Его существующий вид для терминала необходимо сохранить.
- Пользовательские шрифты пока не подключены. Основная папка приложения автоматически синхронизируется с Xcode target.
- В проекте есть XCTest и UI smoke tests. Единственная пакетная UI-зависимость — SwiftTerm; она не затрагивается.

## Scope

- Все нетерминальные экраны, включая панели навигации, поиск, состояния загрузки, пустые состояния, настройки и файловые превью.
- Единые цветовые токены, локально подключаемые стили и bundled-шрифты.
- Новое оформление существующих активных/неактивных состояний без переопределения их смысла.
- Приглушённые иконки технических папок.
- Сохранение текущих подписей, accessibility identifiers и доступности действий.

## Out of Scope

- Любые изменения экрана терминала, его панели, индикатора соединения, рендерера, шрифтов, ввода и вывода.
- Изменения stores, моделей, сервисов, backend, протокола, push routing и бизнес-логики.
- Новые статусы, вычисление активности или количества активных агентов, новые сетевые запросы.
- Перекрашивание содержимого изображений и добавление подсветки синтаксиса.

## Validation

Команды выполнять из `ios/`.

Базовая проверка после каждой задачи:

```bash
xcodebuild build \
  -project tax/tax.xcodeproj \
  -scheme tax \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO
```

Существующие проверки после завершения:

```bash
xcodebuild test \
  -project tax/tax.xcodeproj \
  -scheme tax \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  -only-testing:taxTests

xcodebuild test \
  -project tax/tax.xcodeproj \
  -scheme tax \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  -only-testing:taxUITests
```

Если iPhone 17 недоступен, использовать установленный iOS Simulator. Live relay UI smoke требует существующих переменных окружения; без них этот сценарий штатно пропускается.

Визуально и функционально проверить:
- Все нетерминальные экраны, пустые состояния, загрузку, нажатия и существующие статусы.
- Реальную загрузку custom fonts, длинные названия и пути, Dynamic Type.
- Переходы список → детали → терминал → назад, прямое открытие терминала из push, настройки и файловые экраны: тема не меняет терминал.
- Сохранность навигации, поиска, действий с терминальными сессиями, редактирования и подтверждений.
- Отсутствие изменений в терминальных файлах, stores, моделях и сервисах.

## Acceptance Criteria

- Все экраны, кроме терминала, используют заданную тёмную палитру и типографику.
- Карточки имеют радиус 14 pt, тонкую обводку, отступы и состояние нажатия без теней.
- Существующие активные/неактивные состояния различаются яркостью, полосой и бейджем; смысл статусов не изменён.
- Технические папки визуально приглушены, но остаются доступными.
- Собственные UI-элементы не используют конкурирующие цветовые акценты; нативная семантика системных подтверждений сохранена.
- Терминал, включая его панель и индикатор соединения, выглядит и работает как до изменений.
- Бизнес-логика и доступные пользователю действия не изменены; сборка и существующие применимые проверки проходят.
